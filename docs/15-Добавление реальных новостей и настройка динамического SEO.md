Самым безопасным способом стало копирование одной правильно настроенной реальной новости с последующей заменой всех индивидуальных значений.

## Обязательные поля обычной новости

```text
id                 → пусто / автоматическая нумерация
content_type       → news
locale             → ru
title              → полный заголовок
slug               → уникальный идентификатор URL
subtitle           → краткий анонс
full_text          → полный текст публикации
image_path         → путь к главному изображению

publication_date   → редакционная дата публикации
is_published       → 1
```

Поля, относящиеся к анонсам и событиям, для обычной новости оставлены `NULL`:

```text

event_location

```

Поля аудита пользователей на данном этапе также оставлены `NULL`:

```text

```

# 2. Что означают основные поля базы

## `title`

Полный видимый заголовок статьи.

Пример:

```text
Международная историческая акция «Диктант Победы» в Будапеште
```

## `slug`

Уникальная машинная часть адреса:

```text
diktant-pobedy-v-budapeshte
```

Итоговый URL:

```text
/new-home/ru/news/diktant-pobedy-v-budapeshte
```

## `subtitle`

Краткий анонс, используемый в карточке главной страницы и как резервное SEO-описание.

## `full_text`

Полный текст публикации. Допускается простая HTML-разметка абзацев:

```html
<p>Первый абзац публикации.</p>
<p>Второй абзац публикации.</p>
```

## `image_path`

Пример:

```text
/new-home/img/diktant-pobedy-v-budapeshte.jpeg
```

## `publication_date`

Дата, по которой сайт сортирует новости по хронологии.

## `created_at` и `updated_at`

Эти поля фиксируют фактическое время создания или изменения строки в базе.

В phpMyAdmin в колонке «Функция» было выбрано:

```text
NOW
```

а поле «Значение» оставлено пустым.

Правильное разделение:

```text
publication_date → редакционная дата новости
created_at       → фактическое время добавления строки
updated_at       → фактическое время последнего редактирования
```

# 3. Исправление ошибки с `NOW()`

При вводе возникло предупреждение, потому что одновременно была выбрана функция `NOW` и справа оставалась старая дата.

Неправильно:

```text
Функция: NOW
Значение: 2026-04-24 01:11:54
```

Правильно:

```text
Функция: NOW
Значение: пусто
```

Функция `NOW()` сама формирует текущую дату и время и не требует ручного значения.

# 7. Устранение двойного экранирования `image_path`

Путь изображения должен храниться как обычная строка PHP до момента вывода в HTML.

Правильная подготовка:

```php
$imagePath = trim(
    (string) ($news['image_path'] ?? '')
);
```

Правильный вывод:

```php
src="<?= htmlspecialchars(
    $imagePath,
    ENT_QUOTES,
    'UTF-8'
) ?>"
```

Правильный поток данных:

```text
значение из MySQL
        ↓
обычная строка PHP
        ↓
экранирование только при выводе в HTML
```

Это устраняет двойное экранирование и сохраняет безопасный HTML.

# 8. Подключение динамических SEO-полей к `news.php`

SQL-запрос уже получает:

```sql
seo_title,
seo_description
```

Теперь страница подготавливает значения без преждевременного экранирования:

```php
$seoTitle = trim(
    (string) ($news['seo_title'] ?? '')
);

if ($seoTitle === '') {
    $seoTitle = trim(
        (string) ($news['title'] ?? '')
    );
}

$seoDescription = trim(
    (string) ($news['seo_description'] ?? '')
);

if ($seoDescription === '') {
    $seoDescription = trim(
        (string) ($news['subtitle'] ?? '')
    );
}
```

## Объяснение простыми словами

```text
seo_title заполнен
        ↓
используем seo_title

seo_title пустой
        ↓
используем обычный заголовок статьи
```

Для описания работает такой же резервный механизм:

```text
seo_description заполнен
        ↓
используем его

seo_description пустой
        ↓
используем subtitle
```

Поэтому старые или неполные записи продолжают работать и не создают пустой `<title>` или отсутствующее описание.

# 9. Безопасный вывод SEO в `<head>`

Заголовок выводится так:

```php
<title><?= htmlspecialchars(
    $seoTitle,
    ENT_QUOTES,
    'UTF-8'
) ?></title>
```

Описание выводится только тогда, когда оно не пустое:

```php
<?php if ($seoDescription !== ''): ?>

    <meta
        name="description"
        content="<?= htmlspecialchars(
            $seoDescription,
            ENT_QUOTES,
            'UTF-8'
        ) ?>"
    >

<?php endif; ?>
```

`htmlspecialchars()` защищает итоговую HTML-разметку от специальных символов в значениях из базы.

# 11. Что динамическое SEO делает и чего не гарантирует

Динамические метаданные помогают поисковым системам понять и представить каждую страницу.

```text
уникальные данные статьи
        ↓
уникальный <title>
        ↓
уникальное meta description
        ↓
более понятное отображение в выдаче
```

Но сами по себе эти поля не гарантируют высокую позицию. Ранжирование также зависит от качества текста, соответствия запросу, доступности для робота, ссылок, скорости, мобильной версии и других факторов.

Тестовая версия по-прежнему защищена Basic Authentication и `noindex`, поэтому SEO сейчас подготовлено и проверено технически, но ещё не используется для публичной индексации.
