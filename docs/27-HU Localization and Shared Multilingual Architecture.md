# День 27 — Полноценная HU-версия на общей компонентной архитектуре

# Что было сделано — простыми словами

Цель Дня 27 — превратить подготовленную ранее поддержку второго языка в реально работающую венгерскую версию публичной части сайта, не создавая отдельную копию всей системы.

Если бы эта цель была сформулирована в самом начале, оптимальная последовательность выглядела бы так:

```text
одна архитектура сайта
        ↓
текущая локаль ru / hu
        ↓
общие Header / Hero / Footer
        ↓
локализованная новостная карусель
        ↓
локализованная страница публикации
        ↓
HU-публикации из той же CMS
        ↓
локализованный блок «Студии и курсы»
        ↓
полноценная HU-главная
```

Главный результат: HU-версия перестала быть технической заготовкой. Она использует ту же компонентную основу, что и основная версия, но получает собственные тексты, публикации, даты, подписи интерфейса и маршруты.

---

# Главная задача дня

Нужно было получить рабочую вторую языковую версию без дублирования сайта.

Для этого требовалось:

- использовать одну переменную текущей локали;
- сделать Header двуязычным;
- использовать общий Hero с фильтрацией по локали;
- подключить HU-новости на главной;
- настроить HU-маршруты;
- локализовать страницу отдельной публикации;
- добавить первые реальные HU-публикации;
- перенести на HU-главную весь блок «Студии и курсы»;
- сделать Footer locale-aware;
- сохранить единый набор PHP-, CSS- и JavaScript-компонентов.

---

# 1. Одна переменная управляет языком страницы

HU-входная точка задаёт:

```php
<?php
$currentLocale = 'hu';
?>
```

Общие компоненты получают эту переменную и выбирают нужные подписи и данные.

```text
$currentLocale = 'ru' → RU-интерфейс
$currentLocale = 'hu' → HU-интерфейс
```

Это позволяет отказаться от отдельных копий Header, Hero и Footer для каждого языка.

---

# 2. Header переведён на общую RU/HU-логику

Один `header.php` теперь умеет выводить интерфейс в зависимости от локали.

Локализованы служебные подписи, пункты меню, языковой переключатель, домашняя ссылка, маршруты и элементы доступности.

```text
header.php
   ↓
$currentLocale
   ↓
RU или HU
```

Будущая правка структуры Header выполняется один раз.

---

# 3. Hero используется повторно, а не копируется

Слайдер уже связан с CMS и хранит локаль записи. Теперь тот же публичный компонент используется для HU-версии:

```text
таблица Hero
   ↓
locale = ru / hu
   ↓
hero-slider.php
   ↓
слайды нужного языка
```

Второй язык не потребовал отдельного Hero-модуля.

---

# 4. HU-главная собрана из общих компонентов

Вместо заглушки создан полноценный `/new-home/hu/index.php`.

Его базовая структура:

```php
<?php require_once __DIR__ . '/../includes/header.php'; ?>
<?php require __DIR__ . '/../includes/hero-slider.php'; ?>
<?php require_once __DIR__ . '/../includes/footer.php'; ?>
```

Финальная структура страницы:

```text
Header
Hero
Híreink
Stúdiók és tanfolyamok
Footer
```

---

# 5. Новостная карусель стала locale-aware

Один API-компонент обслуживает обе версии.

Основной принцип выборки:

```sql
WHERE content_type = 'news'
  AND locale = ?
  AND is_published = 1
```

RU-главная получает RU-новости, HU-главная — HU-новости, а неопубликованные материалы не выводятся. Порядок карточек определяется общей логикой сортировки.

---

# 6. Даты локализуются программно

Отображаемый формат даты зависит от языка:

```text
RU → день + месяц + год
HU → год + месяц + день
```

Для HU используется естественная форма, например:

```text
2026. augusztus 24.
```

Редактор сохраняет обычную дату, а публичный PHP-компонент форматирует её для нужной локали.

---

# 7. Подготовлены единые маршруты для RU и HU

Маршрутизация построена вокруг параметра локали:

```text
/{locale}/media/
/{locale}/news/
/{locale}/events/
/{locale}/news/{slug}
```

После разбора URL PHP получает локаль и загружает материал нужного языка. Второй язык использует ту же систему красивых URL, а не отдельный набор страниц.

---

# 8. Локализована страница отдельной публикации

Один `news.php` обслуживает обе языковые версии.

Для HU локализованы дата, ссылка возврата, блок распространения публикации, печатная версия, поля событий, подписи социальных действий, элементы доступности и сообщения копирования ссылки.

```text
locale + slug
     ↓
один news.php
     ↓
нужный контент + нужный интерфейс
```

Чтобы добавить материал на второй язык, не требуется редактировать PHP главной страницы.

3. заполнить текст и SEO-поля;
4. выбрать изображение;
5. задать дату;
6. установить статус «опубликовано».

После этого материал автоматически входит в нужную языковую ленту.
