# Что было сделано — простыми словами

День 16 расширил динамическую архитектуру сайта за пределы обычных новостей.

Сначала уже работающая новостная карусель была аккуратно перемещена с нижней части главной страницы сразу под Hero. Перенос выполнялся как изолированная операция: внутренняя разметка карусели, Hero, блок «Студии и курсы», CSS, JavaScript и логика базы данных не перерабатывались.

Затем на сайте появилась вторая динамическая карусель — для анонсов. В таблицу `home_feed_items` были добавлены четыре реальные записи с `content_type = 'event'`, создан отдельный PHP-компонент, а общий шаблон публикации был расширен так, чтобы открывать новости, анонсы и международные события.

Вертикальная колонка на странице публикации также стала учитывать тип открытого материала:

```text
открыта новость
        ↓
показываем «Другие новости»

открыт анонс
        ↓
показываем «Другие анонсы»

открыто международное событие
        ↓
показываем «Другие международные события»
```

От отдельного контейнера «Международные события» на главной решено отказаться. Контент этого типа будет выводиться в общем блоке:


# 2. Проверка типов материалов в базе данных

Структура поля `home_feed_items.content_type` была проверена запросом:

```sql
SHOW COLUMNS
FROM home_feed_items
LIKE 'content_type';
```

Результат подтвердил:

```text
enum('news','event','international')
```

После этого было проверено количество записей каждого типа:

```sql
SELECT
    content_type,
    COUNT(*) AS total
FROM home_feed_items
GROUP BY content_type
ORDER BY content_type;
```

На тот момент в таблице находились только:

```text
news → 9
```

Это означало, что архитектура для анонсов и международных событий уже существует, но сам контент ещё не внесён.

# 4. Создание `events-carousel.php`

Был создан отдельный компонент:

```text
/docs/new-home/api/events-carousel.php
```

Он построен на проверенной логике `news-carousel.php`, но выбирает:

```sql
WHERE content_type = 'event'
```

Компонент получает специальные поля анонсов:

```text
event_start
event_end
event_location
registration_url
```

Для видимой даты в первую очередь используется `event_start`, а при его отсутствии — `publication_date`.

Логика:

```text
event_start заполнен
        ↓
показываем дату мероприятия

event_start пуст
        ↓
показываем дату публикации
```

В карточке выводятся:

```text
изображение
дата мероприятия
заголовок
место проведения
краткое описание
```

# 6. Подключение анонсов к общему шаблону

Шаблон подробной публикации был расширен с обычных новостей на несколько типов материалов.

Основной SQL-запрос теперь допускает:

```sql
AND content_type IN (
    'news',
    'event',
    'international'
```

В `SELECT` также добавлены:

```text
content_type
```

Теперь один шаблон может открывать:

На текущем этапе все типы временно используют общий красивый маршрут:


Позднее можно создать отдельные маршруты `/event/` и `/international/`, но для рабочей архитектуры Дня 16 это не обязательно.

# 7. Диагностика неработающих ссылок

Сначала при переходе по карточке анонса появлялся белый экран с сообщением:

```text
Новость не найдена.
```

Маршрут работал, потому что запрос доходил до `news.php`. Запись в базе также была проверена SQL-запросом:

```sql
SELECT
    id,
    content_type,
    locale,
    slug,
    is_published,
    deleted_at
FROM home_feed_items
WHERE slug = '...';
```

Запись существовала и имела:

```text
content_type  → event
locale        → ru
is_published  → 1
deleted_at    → NULL
```

Окончательная причина оказалась в некорректных URL-значениях в `home_feed_items`. После исправления адресов страницы анонсов начали открываться.

Эта диагностика наглядно показала цепочку:

```text
карточка карусели
        ↓
сформированный href
        ↓
правило .htaccess
        ↓
SQL-запрос news.php
        ↓
совпадающая запись MySQL
```

Ошибка на любом уровне может выглядеть для пользователя как одна и та же страница 404.

# 8. Контекстная вертикальная колонка

Компонент `latest-news.php` изначально был жёстко привязан к условию:

```sql
WHERE content_type = 'news'
```

Поэтому даже на странице анонса справа выводились обычные новости.

Компонент был переработан: теперь он получает тип текущей публикации из:

```php
$news['content_type']
```

Допустимые значения:

```php
[
    'news',
    'event',
    'international'
]
```

В SQL теперь используется параметр:

```sql
WHERE content_type = ?
```

Параметры передаются так:

```php
$stmtLatestItems->bind_param(
    'sss',
    $currentContentType,
    $currentLocale,
    $currentSlug
);
```

Открытая публикация по-прежнему исключается по `slug`.

## Динамические заголовки

Для русской версии:

```text
news          → Другие новости
event         → Другие анонсы
international → Другие международные события
```

Для венгерской версии уже подготовлены соответствующие локализованные подписи.

## Выбор даты

Для новостей:

```text
publication_date
```

Для анонсов и международных событий:

```text
event_start
```

с резервным переходом на `publication_date`.

# 9. Финальное редакционное решение

Отдельный контейнер «Международные события» на главной странице создаваться не будет.

Вместо этого:

```text
content_type = event
content_type = international
```

будут визуально объединены в секции:

```text
Анонсы РКЦ и международные события
```

Это делает главную страницу компактнее и исключает дублирование похожих блоков.

При этом различие типов в базе сохраняется, потому что оно позволяет:

- фильтровать материалы;
- использовать разные подписи;
- формировать разные боковые ленты;
- создавать архивные страницы;
- управлять мультиязычностью;
- разделять контент редакционно.

Визуальный контейнер общий, но смысловые типы остаются раздельными.
