# 1. Архитектура репозиториев

В базе сохраняются три логических типа:

```text
news          → новости
event         → анонсы РКЦ
international → международные события
```

На первом публичном этапе используются две коллекции:

```text
news
→ content_type = 'news'

events
→ content_type IN ('event', 'international')
```

Отдельная коллекция `international` предусмотрена конфигурацией, но пока не включена как самостоятельный публичный репозиторий.

```php
'news' => [
    'enabled' => true,
    'content_types' => ['news'],
    'route' => 'news',
    'date_field' => 'publication_date',
    'sort_mode' => 'newest_first'
],

'events' => [
    'enabled' => true,
    'content_types' => [
        'event',
        'international'
    ],
    'route' => 'events',
    'date_field' => 'event_start',
    'fallback_date_field' => 'publication_date',
    'sort_mode' => 'upcoming_then_recent',
    'show_type_filter' => true
]
```

Главная остаётся компактной витриной, а репозитории становятся полными каталогами. Когда публикация уходит из карусели из-за `LIMIT`, она не удаляется и остаётся доступной в архиве.

# 3. SQL-поиск, даты и пагинация

Поиск выполняется по полям:

```sql
title
subtitle
tags
event_location
```

Условие строится через подготовленные параметры:

```sql
(
    title LIKE ?
    OR subtitle LIKE ?
    OR tags LIKE ?
    OR event_location LIKE ?
)
```

Для новостей используется `publication_date`, а для событий:

```sql
COALESCE(
    event_start,
    publication_date
)
```

Пагинация строится через отдельный `COUNT(*)`, после чего рассчитываются:

```text
total_items
items_per_page
current_page
total_pages
offset
```

Основной запрос использует:

```sql
LIMIT ?
OFFSET ?
```

# 8. Красивые URL

В `.htaccess` добавлены правила:

```apache
RewriteRule ^(ru|hu)/media/?$ \
    media.php?locale=$1 [L,QSA,NC]

RewriteRule ^(ru|hu)/news/?$ \
    repository.php?collection=news&locale=$1 [L,QSA,NC]

RewriteRule ^(ru|hu)/events/?$ \
    repository.php?collection=events&locale=$1 [L,QSA,NC]

RewriteRule ^(ru|hu)/news/([a-z0-9-]+)/?$ \
    news.php?locale=$1&slug=$2 [L,QSA,NC]
```

Порядок правил позволяет различать:

```text
/ru/news/
→ полный репозиторий

/ru/news/real-slug
→ подробная публикация
```

JavaScript выполняет:

- защиту от повторной инициализации;
- чтение ISO-дат;
- локализованное форматирование;
- построение двух месяцев;
- генерацию 42 ячеек на месяц;
- выделение сегодняшней даты;
- выбор начала и конца диапазона;
- подсветку промежуточных дней;
- переключение месяцев;
- обработку быстрых периодов;
- синхронизацию с `date_from` и `date_to`.

```javascript
function handleDateSelection(clickedDate) {
    if (!selectedStart || selectedEnd) {
        selectedStart = clickedDate;
        selectedEnd = null;
    } else if (
        compareDates(clickedDate, selectedStart) < 0
    ) {
        selectedStart = clickedDate;
        selectedEnd = null;
    } else {
        selectedEnd = clickedDate;
    }

    renderCalendar();
}
```

# 13. Progressive enhancement

Системные поля дат не удалены из HTML. После успешного запуска JavaScript форма получает класс:

```javascript
form.classList.add(
    'has-enhanced-calendar'
);
```

И только после этого CSS скрывает дублирующую строку:

```css
.repository-filter-form.has-enhanced-calendar
.repository-date-row--calendar-sync {
    display: none;
}
```

Логика отказоустойчивости:

```text
JavaScript работает
→ показывается улучшенный календарь
→ технические поля скрываются

JavaScript не загрузился
→ обычные поля дат остаются доступными
```
