# 1. Архитектура репозиториев публикаций

Было принято решение сохранить три логических типа материалов:

```text
news          → новости
event         → анонсы РКЦ
international → международные события
```

При этом на первом этапе посетителю доступны два полноценных репозитория:

```text
news
→ только content_type = news

events
→ content_type IN ('event', 'international')
```

Отдельная коллекция `international` уже предусмотрена конфигурацией, но пока отключена как самостоятельная публичная страница.

Таким образом:

```text
три редакционных типа
        ↓
два публичных репозитория
        ↓
возможность будущего разделения без переноса записей
```

## Принцип «витрина и полный каталог»

Главная страница остаётся витриной свежих публикаций:

```text
ограниченная карусель
        ↓
только несколько актуальных карточек
```

Репозиторий выполняет другую функцию:

```text
все опубликованные материалы
        ↓
поиск
        ↓
фильтры
        ↓
пагинация
```

Когда новая запись вытесняет старую из карусели из-за `LIMIT`, старая публикация не удаляется и автоматически остаётся доступной в полном репозитории.


## Поиск

Поисковая строка проверяет:

```sql
title
subtitle
tags
event_location
```

Условие строится с подготовленными параметрами:

```sql
(
    title LIKE ?
    OR subtitle LIKE ?
    OR tags LIKE ?
    OR event_location LIKE ?
)
```

## Диапазон дат

Для новостей используется:

```text
publication_date
```

Для событий:

```sql
COALESCE(
    event_start,
    publication_date
)
```

Это означает:

```text
event_start заполнен
        ↓
фильтруем по дате события

event_start отсутствует
        ↓
используем дату публикации
```

## Пагинация

Сначала выполняется отдельный запрос:

```sql
SELECT COUNT(*) AS total
FROM home_feed_items
WHERE ...
```

Затем рассчитываются:

```text
total_items
items_per_page
current_page
total_pages
offset
```

Основной запрос получает только записи текущей страницы:

```sql
LIMIT ?
OFFSET ?
```

## Сортировка

Новости:

```text
самые новые первыми
```

Анонсы и международные события:

```text
сначала ближайшие будущие события
затем прошедшие — от новых к старым
```

# 7. Диагностика подключения MySQL

При первом открытии репозитория появилась ошибка:

```text
php_network_getaddresses:
getaddrinfo failed:
Name or service not known
```

Страница при этом уже собиралась визуально:

- Header загружался;
- стили работали;
- заголовок отображался;
- форма поиска была видна;
- выводилось сообщение «Не удалось загрузить публикации».

Это позволило локализовать проблему именно в подключении к базе данных.

Причина:

```text
неверное значение хоста MySQL в repository.php
```

Рабочий блок `new mysqli(...)` был перенесён из уже действующего серверного компонента.

После исправления репозиторий получил восемь опубликованных новостей из `home_feed_items`.

Эта ситуация подтвердила полезность разделения слоёв:

```text
HTML и CSS работают
        ↓
ошибка находится только в MySQL-подключении
        ↓
после исправления данные появляются без переделки интерфейса
```

# 11. Настройка красивых URL

В `.htaccess` были добавлены правила:

```apache
RewriteRule ^(ru|hu)/media/?$ media.php?locale=$1 [L,QSA,NC]

RewriteRule ^(ru|hu)/news/?$ repository.php?collection=news&locale=$1 [L,QSA,NC]

RewriteRule ^(ru|hu)/events/?$ repository.php?collection=events&locale=$1 [L,QSA,NC]
```

Правило отдельной публикации осталось ниже:

```apache
RewriteRule ^(ru|hu)/news/([a-z0-9-]+)/?$ news.php?locale=$1&slug=$2 [L,QSA,NC]
```

Порядок правил позволяет различать:

```text
/ru/news/
→ репозиторий

/ru/news/real-slug
→ подробная публикация
```

После проверки технические ссылки в `index.php` и `media.php` были заменены красивыми адресами.

Итоговые публичные маршруты:

```text
/new-home/ru/media/
/new-home/ru/news/
/new-home/ru/events/
/new-home/ru/news/<real-slug>
```

```text
первый клик

        ↓

        ↓
```

## Связь с сервером

JavaScript не выполняет SQL-запросов.

Он только записывает значения в существующие поля:

```text
date_from
date_to
```

После нажатия «Применить» браузер формирует GET-запрос, а `repository-query.php` выполняет серверную фильтрацию.

```text
календарь
        ↓
GET-параметры
        ↓
подготовленный SQL-запрос
        ↓
отфильтрованные карточки
```

# 14. Компактный дизайн календаря

Первый вариант календаря был функциональным, но занимал слишком много вертикального пространства.

После сравнения с выбранным образцом интерфейс был переработан.

Финальная компоновка на компьютере:

```text
‹   первый месяц   второй месяц   ›   Сегодня
                                         Завтра
                                         Ближайшая неделя
                                         Ближайший месяц

                                         Применить
                                         Сбросить
```

Были уменьшены:

- внутренние отступы;
- высота календарных ячеек;
- размер заголовков месяцев;
- размер стрелок;
- ширина правой колонки;
- общий вертикальный размер блока.

Правая колонка стала отдельной областью быстрых действий.

## Progressive enhancement

Нижние системные поля дат не удалены из HTML.

После успешного запуска JavaScript форма получает класс:
