# 1. Красивые URL

Ранее страница открывалась по техническому адресу:

```text
/new-home/news.php?slug=den-russkogo-yazyka-v-rkc
```

После настройки адрес стал выглядеть так:

```text
/new-home/ru/news/den-russkogo-yazyka-v-rkc
```

В `.htaccess` добавлено правило:

```apache
RewriteRule ^(ru|hu)/news/([a-z0-9-]+)/?$ news.php?locale=$1&slug=$2 [L,QSA,NC]
```

## Что это означает для новичка

Файл физически не перемещается в отдельную папку `ru/news`. Apache читает красивый адрес и незаметно для посетителя передаёт в `news.php` два значения:

```text
ru                              → язык

den-russkogo-yazyka-v-rkc       → идентификатор новости
```

Упрощённый алгоритм:

```text
браузер просит красивый URL
        ↓
.htaccess разбирает адрес
        ↓
news.php получает locale и slug
        ↓
PHP ищет нужную строку в MySQL
        ↓
шаблон выводит найденную новость
```

Старые технические ссылки пока сохранены. Это уменьшает риск сломать уже существующие переходы.

# 2. Что такое slug и почему без него новость исчезала

`slug` — это короткое уникальное имя публикации для URL.

Пример:

```text
Заголовок:
В РКЦ отметили День русского языка

slug:
den-russkogo-yazyka-v-rkc
```

Несколько реальных публикаций имели:

```text
slug = NULL
```

Компонент не мог создать для них ссылку, поэтому пропускал их. После диагностики этим публикациям были назначены уникальные slug:

```text
na-territorii-hrama-usypalnitsy
muzykalnyy-podarok-dlya-gostey-rkc
den-russkogo-yazyka-v-rkc
```

## Простая аналогия

Заголовок новости — это полное имя человека, а `slug` — уникальный номер его карточки в каталоге. Если номера нет, система не понимает, какую страницу открывать.

# 3. Проверка языка и получение новости

В `news.php` принимается язык страницы:

```php
$locale = strtolower(
    trim((string) ($_GET['locale'] ?? 'ru'))
);
```

Допускаются только:

```php
$allowedLocales = ['ru', 'hu'];
```

Новость ищется одновременно по `slug` и языку:

```sql
WHERE slug = ?
  AND content_type = 'news'
  AND locale = ?
  AND is_published = 1
  AND deleted_at IS NULL
```

## Зачем столько условий

Они работают как последовательная проверка пропуска:

```text
это именно новость?
        ↓
она относится к нужному языку?
        ↓
она опубликована?
        ↓
она не находится в корзине?
        ↓
можно показывать посетителю
```

Знаки `?` означают подготовленный SQL-запрос. Значения передаются отдельно от текста запроса, что безопаснее прямой склейки строк.

# 4. Вертикальный блок «Другие новости»

Файл:

```text
/docs/new-home/includes/latest-news.php
```

Он выводит не больше трёх публикаций:

```php
$otherNewsLimit = 3;
```

Основной принцип выборки:

```sql
WHERE content_type = 'news'
  AND locale = ?
  AND is_published = 1
  AND deleted_at IS NULL
  AND slug IS NOT NULL
  AND slug <> ''
  AND slug <> ?
ORDER BY publication_date DESC, id DESC
LIMIT 3
```

## Перевод этого SQL на обычный язык

```text
возьми только новости
        ↓
только на текущем языке
        ↓
только опубликованные
        ↓
не бери записи из корзины
        ↓
не бери записи без адреса
        ↓
не повторяй статью, которая уже открыта
        ↓
поставь самые свежие сверху
        ↓
покажи максимум три
```

Список не хранится вручную в HTML. При добавлении новой публикации компонент сам пересчитывает, какие три новости являются актуальными.

# 5. Мягкое удаление тестовой новости

Вместо безвозвратного `DELETE` выполнено:

```sql
UPDATE home_feed_items
SET
    is_published = 0,
    deleted_at = NOW()
WHERE id = 6
  AND slug = 'testovaya-novost'
LIMIT 1;
```

## Что произошло фактически

Запись осталась в базе, но получила два признака:

```text
is_published = 0   → не показывать на сайте

deleted_at = дата  → считать помещённой в корзину
```

Это аналог перемещения файла в корзину компьютера, а не окончательного уничтожения. Позже административная CMS сможет восстановить такую запись.

`LIMIT 1` служит дополнительной страховкой: запросу разрешено изменить только одну строку.

# 6. Перестройка страницы новости

Страница разделена на две логические части:

```text
news-layout
    ├── news-article
    │      ├── дата
    │      ├── заголовок
    │      ├── теги
    │      ├── фотография
    │      └── текст
    │
    └── news-sidebar
           ├── «Вернуться на главную»
           └── «Другие новости»
```

## Почему это лучше

Раньше дата и заголовок находились над всей двухколоночной конструкцией. Теперь основная публикация относится к левой колонке, а служебная навигация — к правой.

Визуальный результат:

```text
дата и заголовок статьи      Вернуться на главную
главная фотография           Другие новости
полный текст                  три карточки
```

# 7. Переход сразу к области чтения

В страницу добавлена метка:

```html
<main class="news-page" id="news-reading">
```

Ссылка на другую статью заканчивается так:

```text
#news-reading
```

Пример:

```text
/new-home/ru/news/den-russkogo-yazyka-v-rkc#news-reading
```

## Как это работает

Часть после `#` — внутренний указатель для браузера: после загрузки страницы найти элемент с таким `id` и прокрутить экран к нему.

Поэтому посетителю больше не приходится после каждого перехода вручную прокручивать большой хедер.

# 8. Очистка `news.css`

В прежнем CSS одновременно присутствовали старые и новые варианты одних и тех же правил, а также лишние закрывающие скобки. В такой ситуации браузер применяет последнее подходящее правило, и результат становится трудно предсказуемым.

Файл был заменён единой согласованной версией.

Основная сетка:

```css
.news-layout {
    display: grid;
    grid-template-columns: minmax(0, 1fr) 320px;
    gap: 40px;
    align-items: start;
}
```

## Простое объяснение

```text
minmax(0, 1fr) → левая колонка занимает всё оставшееся место
320px           → правая колонка имеет фиксированную ширину
40px            → расстояние между ними
```

На экране меньше 900 пикселей:

```css
.news-layout {
    grid-template-columns: 1fr;
}
```

Обе колонки складываются одна под другой, что делает страницу пригодной для телефона.

---

# 9. Почему менялся параметр `?v=` у CSS

Подключение выглядит так:

```html
<link rel="stylesheet" href="/new-home/css/news.css?v=20260730-2">
```

Браузер может хранить старый CSS в кэше. Изменение значения после `?v=` заставляет его считать адрес новым и загрузить свежий файл.

Сам CSS от этого не меняется. Это только способ сказать браузеру: «не используй старую сохранённую копию».

# 10. Экранирование путей и ссылок

Правильный принцип:

```text
получить исходное значение из MySQL
        ↓
хранить его в PHP без изменения
        ↓
экранировать непосредственно при выводе в HTML
```

Пример:

```php
$imagePath = trim(
    (string) ($item['image_path'] ?? '')
);
```

И только при выводе:

```php
src="<?= htmlspecialchars(
    $imagePath,
    ENT_QUOTES,
    'UTF-8'
) ?>"
```

`htmlspecialchars()` не изменяет файл изображения. Она защищает HTML-разметку от специальных символов в строке.

# 11. Перевод карусели главной на красивые URL

Файл:

```text
/docs/new-home/api/news-carousel.php
```

Для каждой карточки берётся `slug` и строится адрес:

```php
$targetUrl =
    '/new-home/ru/news/' .
    rawurlencode($slugValue);
```

Если у старой записи `slug` отсутствует, временно используется `target_url` как резервный вариант.

## Почему `index.php` и JavaScript не пришлось переписывать

PHP-компонент уже получает до восьми карточек:

```sql
LIMIT 8
```

А `content-carousel.js` считает реальное количество карточек после загрузки страницы:

```text
1 карточка на телефоне
2 карточки на планшете
4 карточки на компьютере
```

Следовательно, после добавления ещё двух записей в MySQL карусель сама создаст дополнительную страницу прокрутки.

# 12. Как теперь добавить новые новости

Не требуется вручную создавать новую HTML-страницу для каждой публикации.

Достаточно добавить запись в:

```text
home_feed_items
```

с полями:

```text
title / заголовок
slug / адрес
subtitle / краткий анонс
full_text / полный текст
image_path / путь к фотографии
publication_date / дата
content_type = news
locale = ru
is_published = 1
deleted_at = NULL
```

После этого одна запись автоматически участвует сразу в трёх местах:

```text
MySQL
  ├── карточка главной карусели
  ├── отдельная страница через news.php
  └── вертикальная лента «Другие новости»
```

В этом состоит главное преимущество динамического сайта: контент вводится один раз, а разные компоненты получают его из общего источника.

# 13. Подсветка заголовков

Для вертикальной ленты подготовлен эффект:

```css
.latest-news-item:hover .latest-news-title,
.latest-news-item:focus-visible .latest-news-title {
    color: #5367a5;
}
```

`hover` работает при наведении мышью, а `focus-visible` — при навигации клавиатурой. Синий цвет согласован с подсветкой горизонтального меню.
