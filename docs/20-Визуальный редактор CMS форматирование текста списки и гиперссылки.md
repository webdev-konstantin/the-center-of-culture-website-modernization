# Что было сделано — простыми словами

В День 20 редактор публикаций научился работать с текстом почти так же, как обычный текстовый процессор.

Раньше поле `full_text` уже сохраняло HTML, но содержимое приходилось оформлять вручную. Теперь редактор показывает текст визуально и позволяет применять форматирование кнопками.

Сотрудник Центра ДПО может:

```text
написать или вставить текст
        ↓
выделить нужный фрагмент
        ↓
выбрать форматирование
        ↓
сохранить публикацию
```

Поддерживаются абзацы, заголовки, полужирный текст, курсив, подчёркивание, цитаты, маркированные и нумерованные списки, гиперссылки и очистка форматирования.

При этом CMS продолжает хранить обычную HTML-разметку в поле `full_text`. Новый интерфейс не меняет существующую серверную модель, а делает работу с ней понятной для редактора сайта.

Полный маршрут данных теперь выглядит так:

```text
визуальное редактирование
        ↓
формирование HTML
        ↓
поле full_text
        ↓
таблица home_feed_items
        ↓
публичная страница публикации
```

Работа проверена не только внутри административной панели: тестовая публикация успешно сохранила заголовок, списки и гиперссылку, а затем корректно отобразила их на публичной странице.

# 1. Визуальная область редактирования

Для основного текста была подключена редактируемая HTML-область:

```html
<div
    contenteditable="true"
    data-wysiwyg-editor
></div>
```

Пользователь видит оформленный материал, а не набор тегов.

Исходное поле формы при этом сохранено:

```text
name="full_text"
```

Оно остаётся источником данных для PHP и базы данных.

Архитектура разделяет две роли:

```text
визуальная область
        ↓
удобство редактирования

поле full_text
        ↓
передача HTML на сервер
```

---

# 2. Панель форматирования

Над текстовой областью создана единая панель команд.

Доступны:

```text
отмена действия
повтор действия
обычный абзац
H2
H3
полужирный текст
курсив
подчёркивание
маркированный список
нумерованный список
цитата
ссылка
удаление ссылки
очистка форматирования
```

Каждая кнопка имеет атрибут:

```html
data-wysiwyg-command
```

Один JavaScript-обработчик определяет выбранную команду и применяет её к текущему выделению.

Это позволяет развивать панель дальше без создания отдельной логики для каждой кнопки в HTML.

---

# 3. Синхронизация с `full_text`

Ключевой функцией редактора стала:

```js
syncWysiwygToTextarea();
```

Она:

1. получает HTML из визуальной области;
2. нормализует теги форматирования;
3. записывает результат в `full_text`;
4. отправляет событие `input`;
5. повторно запускается перед отправкой формы.

Таким образом, пользователь работает визуально, но сервер получает обычный HTML.

```text
До чего дошёл прогресс!
```

после форматирования может быть сохранён как:

```html
До чего дошёл <a href="https://ruscenter.hu/">прогресс!</a>
```

---

# 4. Абзацы и заголовки

Редактор поддерживает основные структурные элементы публикации:

```html
<p>Обычный абзац</p>

<h2>Заголовок раздела</h2>

<h3>Подзаголовок</h3>
```

Это позволяет формировать длинные материалы с понятной иерархией без ручного ввода тегов.

Заголовки сохраняются в `full_text` и корректно отображаются после повторного открытия публикации.

---

# 5. Начертание текста

К выделенному фрагменту можно применить:

```html
<strong>полужирный текст</strong>
<em>курсив</em>
<u>подчёркнутый текст</u>
```

При синхронизации браузерные теги `<b>` и `<i>` приводятся к более понятным семантическим вариантам:

```text
b → strong
i → em
```

---

# 6. Маркированные и нумерованные списки

В редакторе работают два типа списков.

Маркированный список:

```html
<ul>
    <li>Первый пункт</li>
    <li>Второй пункт</li>
    <li>Третий пункт</li>
</ul>
```

Нумерованный список:

```html
<ol>
    <li>Первый шаг</li>
    <li>Второй шаг</li>
</ol>
```

Редактор преобразует выбранные строки в отдельные элементы `<li>` и сохраняет готовую структуру в `full_text`.

Проверка подтвердила, что оба списка сохраняются и повторно открываются без потери структуры.

# 7. Добавление гиперссылок

Для ссылки создано отдельное диалоговое окно.

Рабочий сценарий:

```text
выделить слово или фразу
        ↓
нажать «Ссылка»
        ↓
ввести полный URL
        ↓
нажать «Добавить ссылку»
        ↓
получить кликабельный текст
```

Если текст не выделен, редактор сообщает:

```text
Сначала выделите текст, который должен стать ссылкой.
```

Для сохранения выделенного фрагмента используются функции:

```js
saveWysiwygSelection();
restoreWysiwygSelection();
```

Перед открытием окна выделение сохраняется. После ввода URL оно восстанавливается, и ссылка применяется именно к выбранному тексту.

---

# 8. Проверка URL

Адрес проверяется перед добавлением.

Разрешены только:

```text
https://
http://
```

Если адрес не соответствует правилам, редактор показывает сообщение:

```text
Введите полный адрес, начинающийся с https:// или http://
```

Проверка выполняется до формирования `<a href="...">`, поэтому ошибочный адрес не попадает в текст публикации.

---

# 9. Единая функция применения ссылки

Создание ссылки выполняет одна функция:

```js
applyWysiwygLink();
```

Она последовательно выполняет:

```text
проверку элементов редактора
        ↓
проверку сохранённого выделения
        ↓
проверку URL
        ↓
восстановление фокуса и выделения
        ↓
создание ссылки
        ↓
синхронизацию full_text
```

Функция вызывается:

- кнопкой «Добавить ссылку»;
- клавишей `Enter` в поле URL.

Оба способа используют одну и ту же проверенную логику.

---

# 10. Удаление ссылки

Кнопка «Убрать ссылку» удаляет тег `<a>` из выбранного фрагмента, сохраняя сам текст.

```html
<a href="https://ruscenter.hu/">прогресс!</a>
```

превращается в:

```text
прогресс!
```

После удаления содержимое снова синхронизируется с `full_text`.

---

# 11. Очистка форматирования

Команда «Очистить» удаляет применённое начертание и возвращает выбранный текст к обычному абзацу.

Она полезна при вставке материала из Word, электронной почты или другого сайта, когда вместе с текстом переносится лишнее оформление.
