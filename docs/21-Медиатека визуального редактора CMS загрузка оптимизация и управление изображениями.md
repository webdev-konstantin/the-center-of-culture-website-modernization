Однако единого каталога изображений не существовало: нельзя было удобно увидеть все файлы, найти нужную картинку, заполнить метаданные, выбрать несколько карточек или безопасно удалить файл через CMS.

Теперь изображения объединены в отдельном административном разделе:

```text

```

Медиатека показывает:

```text

        +
существующие изображения сайта из /new-home/img/
        ↓

```

Администратор может искать изображения, фильтровать их по источнику, менять размер карточек, открывать подробные сведения, редактировать метаданные, выделять несколько файлов через `Ctrl` и выполнять групповые операции.

Новые изображения автоматически оптимизируются для веба и регистрируются в базе данных. При открытии медиатеки последняя добавленная запись становится активной и показывается в правом столбце.

# 1. Создание таблицы медиатеки

Для хранения сведений об изображениях создана таблица:

```text
media_items
```

Бинарное содержимое файла не помещается в MySQL. Изображение остаётся в файловой системе, а база хранит его описание.

```text
изображение на сервере
        +
запись media_items
        ↓
управляемый объект медиатеки
```

Основные технические поля:

```text
id
file_path
stored_filename
original_filename
original_mime_type
original_file_size
original_width
original_height
mime_type
file_extension
file_size
width
height
file_hash
source_kind
created_at
updated_at
```

Редакционные поля:

```text
title
alt_text
caption
annotation
credit
source_url
```

Один файл теперь можно описать один раз и в дальнейшем использовать повторно.

# 2. Метаданные изображения

Медиатека отвечает не только на вопрос «где лежит файл», но и на вопросы:

```text
что изображено
кто автор
откуда получено изображение
какую подпись показать
какой alt-текст использовать
```

Для этого добавлены:

- **Название** — внутреннее понятное имя;
- **Альтернативный текст** — описание для доступности и поиска;
- **Подпись** — будущий текст под изображением;
- **Внутренняя аннотация** — служебное описание для CMS;
- **Автор или правообладатель** — сведения об авторстве;
- **Ссылка на источник** — адрес исходной публикации или ресурса.

# 3. Поддерживаемые форматы

Загрузчик принимает:

```text
JPEG
JPG
PNG
WebP
```

Расширения `.jpg` и `.jpeg` относятся к формату JPEG и обрабатываются одинаково.

Фотографии с iPhone поддерживаются, если сохранены или экспортированы как JPEG, JPG, PNG либо WebP.

HEIC и HEIF в текущий этап не включены. Для них потребуется отдельная серверная поддержка Imagick/ImageMagick либо предварительное преобразование файла.

# 4. Автоматическая веб-оптимизация

Новый файл не просто копируется на сервер.

```text
исходное изображение
        ↓
проверка формата и размера
        ↓
чтение ширины и высоты
        ↓
уменьшение при необходимости
        ↓
преобразование в WebP
        ↓
сохранение файла
        ↓
создание записи media_items
```

WebP уменьшает объём страницы и ускоряет загрузку на компьютерах и мобильных устройствах.

Проверенный пример:

```text
исходный JPEG: 378 301 байт
        ↓
WebP: 227 206 байт
        ↓
размеры: 1024 × 768
```

Оптимизация снижает:

- нагрузку на сервер;
- мобильный трафик;
- время открытия публикации;
- объём дискового пространства;
- риск появления слишком тяжёлых страниц.

# 5. Безопасные имена файлов

Загруженное изображение получает уникальное серверное имя.

Пример:

```text
20260808-120649-eb5dfdaf885eca453d63eecc07a39dcd.webp
```

Это позволяет:

- избежать совпадения имён;
- убрать пробелы и небезопасные символы;
- не зависеть от языка исходного имени;
- безопасно обрабатывать файлы автоматически.

Исходное имя сохраняется отдельно в `original_filename`.

# 7. API медиатеки

Создан серверный обработчик:

```text
/new-home/admin/media-library-api.php
```

Основные действия:

```text
list
update
remove
delete_file
```

## list

Возвращает изображения с учётом поиска и выбранного источника.

## update

Сохраняет метаданные.

## remove

Убирает запись из медиатеки, оставляя файл на сервере.

## delete_file

Физически удаляет файл и соответствующую запись.

Ответ возвращается в JSON, поэтому интерфейс обновляется без полной перезагрузки страницы.

# 17. Групповые операции

Разделены два разных действия.

## Убрать из медиатеки

Удаляет запись `media_items`, но оставляет файл.

## Удалить физически

Стирает файл с сервера и удаляет его запись.

```text
убрать из каталога CMS
        ≠
стереть файл с сервера
```

Перед физическим удалением показывается одно стандартное подтверждение. Избыточное второе окно с вводом слова «УДАЛИТЬ» было убрано.

# 18. Защита изображений публикаций

Перед окончательным удалением сервер проверяет, используется ли `file_path` в `home_feed_items.image_path`.

```text
команда удаления
        ↓
проверка публикаций
        ↓
файл используется
        → операция блокируется

файл не используется
        → физическое удаление разрешено
```

Это предотвращает исчезновение главного изображения с опубликованной страницы.

Путь также проверяется на принадлежность разрешённым каталогам, поэтому CMS не может стереть произвольный серверный файл.
