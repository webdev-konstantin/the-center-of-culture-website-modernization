# Что было сделано — простыми словами

День 26 начался сразу после завершения Дня 25.

К этому моменту собственный редактор Hero-слайдера уже был создан и подключён к CMS. Но первое реальное использование показало важную вещь: **создать редактор — ещё не значит полностью закончить интеграцию**.

При работе с новыми слайдами проявились проблемы на стыке административной части и публичной главной страницы:

- потребовалось доработать поведение переходов после операций в `hero-slides.php`;
- новый слайд сохранялся в системе, но не сразу появлялся на главной;
- ссылка «Подробнее» не выводилась так, как ожидалось;
- после промежуточного восстановления кнопки правая стрелка могла перескочить с первого слайда сразу на третий;
- позднее выяснилось, что браузер вообще продолжал получать старую версию публичного `hero-slider.php`.

Поэтому День 26 стал большим этапом **доводки всей цепочки Hero от редактора CMS до поведения пользователя на главной странице**.

В финале отдельная кнопка «Подробнее» была вообще исключена из интерфейса. Вместо неё весь активный Hero-слайд стал кликабельным и открывает ссылку, сохранённую именно для текущего слайда.

Итоговая логика теперь выглядит так:

```text
администратор редактирует слайд в CMS
        ↓
данные сохраняются в hero_slides
        ↓
hero-slider.php получает активные записи
        ↓
hero.js переключает текущий слайд
        ↓
вся площадь активного Hero является ссылкой
        ↓
клик открывает URL именно текущего слайда
```

# Главная задача дня

Не просто «добавить кнопку» или «починить стрелку», а довести уже созданный в День 25 Hero-модуль до состояния, когда вся цепочка работает согласованно:

```text
CMS → база данных → PHP-компонент → CSS → JavaScript → браузер
```

То есть то, что администратор сохраняет в редакторе, должно именно в таком виде появляться и работать на публичной странице.

# 1. Продолжение Дня 25: проверка административного Hero-редактора

Работа Дня 26 началась с продолжения интеграции `hero-slides.php`.

Редактор уже умел создавать и изменять записи, но после реальных операций потребовалась дополнительная проверка поведения переходов и возврата пользователя внутри административного интерфейса.

Вместо переписывания редактора целиком была сохранена уже созданная архитектура Дня 25 и корректировались только проблемные участки.

Это важный принцип всего проекта:

```text
работающий модуль
        ↓
локальная проблема
        ↓
проверка конкретной цепочки
        ↓
минимальная исправляющая правка
```

а не очередная полная замена CMS.

# 2. Новый слайд есть в CMS, но его нет на главной

Следующий реальный тест оказался особенно полезным.

В редактор Hero был добавлен новый слайд. Данные в системе отображались, однако на главной странице новый элемент не появился.

Это означало, что проверять нужно уже не только административную форму, а всю цепочку доставки данных:

```text
hero-slides.php
        ↓
таблица hero_slides
        ↓
hero-slider.php
        ↓
index.php
        ↓
HTML главной страницы
```

Именно с этого момента Hero стал рассматриваться не как отдельная форма CMS и не как отдельная карусель, а как единый сквозной компонент.

---

# 3. Проверка публичного `hero-slider.php`

Публичный компонент отвечает за то, какие записи реально попадут на главную страницу.

В нём была сохранена логика:

- загрузки только опубликованных слайдов;
- работы с выбранной локалью;
- сортировки по заданному порядку;
- режима с затемнением;
- режима «только изображение»;
- безопасного вывода текста и URL.

Отдельное внимание потребовалось ссылке перехода.

URL хранится в записи Hero и должен использоваться публичным слайдом независимо от того, выбран ли текстовый режим или режим изображения без затемнения.

---

# 4. Возвращение «Подробнее» как промежуточное решение

На одном из этапов стало видно, что в Hero отсутствует ожидаемая ссылка «Подробнее».

Проблема оказалась не только визуальной. В некоторых режимах сам HTML-элемент кнопки не создавался, поэтому попытка исправить ситуацию одним CSS не могла дать результата.

Была восстановлена логика вывода ссылки и отдельно предусмотрено её отображение для режима «только изображение».

Промежуточный результат был успешным: «Подробнее» появилась и получила аккуратную корпоративную рамку, читаемую на светлом фоне.

Но это решение не стало финальным — после проверки интерфейса было принято более простое решение: **вообще отказаться от отдельной кнопки и сделать ссылкой весь слайд**.

---

# 5. Обнаружена проблема навигации: 1 → 3 вместо 1 → 2

После восстановления внешнего вида Hero проявилась другая проблема.

При нажатии правой стрелки слайдер мог перейти с первого слайда сразу на третий, минуя второй.

При этом сама функция следующего слайда в JavaScript математически делала только:

```text
текущий индекс + 1
```

Поэтому искать «ошибку +2» в одной строке было бессмысленно.

Проверка была расширена на:

- структуру DOM;
- возможные повторные подключения Hero;
- порядок слайдов;
- обработчики стрелок;
- автопрокрутку;
- актуальность загруженного JavaScript.

---

# 6. Проверка реального `index.php`

Вместо работы по старым версиям был проверен конкретный рабочий `index.php`.

Особенно важным оказался исторический фрагмент, где вокруг динамического подключения мог оставаться старый внешний контейнер:

```php
<section class="hero">
    <?php require __DIR__ . '/includes/hero-slider.php'; ?>
</section>
```

При том что сам `hero-slider.php` уже создаёт собственный:

```html
<section class="hero">
```

В рабочей структуре оставлено только одно подключение:

```php
<?php require __DIR__ . '/includes/hero-slider.php'; ?>
```

То есть Hero больше не должен иметь второй устаревший контейнер вокруг динамического компонента.

---

# 7. Проверка `footer.php` и загрузки JavaScript

Также был проверен общий подвал.

Нужно было исключить вариант, при котором `hero.js` подключается второй раз и один клик получает два обработчика.

Проверка показала, что `footer.php` не создаёт повторного подключения Hero-скрипта.

Это позволило не вносить ненужные изменения в общий подвал и продолжить поиск в самой логике Hero.

---

# 8. Стабилизация `hero.js`

Исходный алгоритм переключал индекс корректно, но автопрокрутка была построена на постоянном `setInterval`.

Для более предсказуемого поведения при ручном клике логика была переведена на управляемый `setTimeout`.

Теперь после ручного действия происходит:

```text
остановить текущий таймер
        ↓
выполнить ровно одно переключение
        ↓
создать новый таймер автопрокрутки
```

Также добавлена защита от повторной инициализации одного и того же Hero:

```text
если Hero уже инициализирован → второй набор обработчиков не создавать
```

Это сделало поведение стрелок более контролируемым и уменьшило количество возможных гонок между ручным и автоматическим переключением.

# 9. Очистка CSS-подключений и кеша

В `index.php` оставалась ссылка на промежуточный файл:

```text
hero-day25-additions.css
```

Но такого файла в текущей структуре уже не было.

Поэтому все необходимые публичные стили Hero были сведены к существующему:

```text
/new-home/css/hero.css
```

Для CSS и JavaScript использовано версионирование URL:

```text
hero.css?v=20260829-...
hero.js?v=20260829-...
```

Это устраняет типичную ситуацию, когда файл на сервере уже изменён, а браузер продолжает показывать старую закешированную версию.

# 10. Финальное UX-решение: весь Hero становится ссылкой

После того как отдельная кнопка «Подробнее» уже была восстановлена и визуально оформлена, интерфейс был переосмыслен.

Для Hero-слайдера естественнее оказалось следующее поведение:

- наведение на активный слайд показывает кликабельный курсор;
- клик по основной площади открывает материал;
- стрелки и точки остаются отдельными элементами управления.

В `hero-slider.php` для каждого слайда с корректным `button_url` теперь создаётся прозрачная ссылка:

```html
<a class="hero-slide-link" href="..."></a>
```

Она занимает весь слайд.

Отдельная визуальная кнопка больше не требуется.

---

# 11. Правильная иерархия слоёв

Чтобы полноэкранная ссылка не перекрывала стрелки и точки, элементы разнесены по `z-index`:

```text
z-index 5 → стрелки и точки
z-index 3 → прозрачная ссылка слайда
z-index 2 → текст Hero
z-index 1 → затемнение
            изображение
```

В результате:

- клик по изображению или свободной части Hero открывает ссылку текущего слайда;
- клик по стрелке только перелистывает;
- клик по точке только выбирает слайд.

# 12. Почему курсор сначала не стал кликабельным

После добавления CSS для `.hero-slide-link` ожидаемого курсора сначала не появилось.

Вместо очередной правки «на глаз» была открыта Chrome DevTools Console.

Проверка:

```js
document.querySelectorAll('.hero-slide-link').length
```

дала:

```text
0
```

А проверка старых элементов:

```js
document.querySelectorAll('.hero-button, .hero-image-action').length
```

дала:

```text
4
```

Это был ключевой момент дня.

CSS для новой ссылки уже существовал, но **самой новой ссылки в фактическом DOM вообще не было**. Вместо неё браузер получал старые кнопки.

---

# 13. Build-маркер подтвердил старую версию PHP

Чтобы перестать гадать, какая версия компонента реально выполняется на сервере, в новый `hero-slider.php` был добавлен диагностический маркер:

```html
data-hero-build="20260829-clickable-v1"
```

В Console выполнена проверка:

```js
document.querySelector('.hero')?.dataset.heroBuild || 'НЕТ МАРКЕРА'
```

Первый результат:

```text
НЕТ МАРКЕРА
```

Это подтвердило, что браузер не получает тот новый PHP-файл, который ожидался.

Именно поэтому предыдущие CSS-правки не могли заставить появиться `.hero-slide-link`: сервер продолжал отдавать старую HTML-разметку.

# 15. Исчезновение «Подробнее» при загрузке страницы

До финальной замены при обновлении страницы слово «Подробнее» могло кратко появляться в левом верхнем углу ещё до полной загрузки Hero.

Причина стала понятна после проверки DOM: старая разметка по-прежнему содержала обычные текстовые ссылки-кнопки.

После перехода на прозрачную ссылку всего слайда текстового элемента «Подробнее» в публичном Hero больше нет.

Поэтому исчез и сам артефакт начальной загрузки.
