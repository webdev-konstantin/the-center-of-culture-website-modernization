# Что было сделано — простыми словами

День 26 стал не днём добавления нового большого модуля, а днём доведения Hero-слайдера до законченного рабочего состояния.

После подключения Hero к CMS оставались две заметные проблемы:

- стрелки перелистывания могли вести себя нестабильно;
- переход к материалу был привязан к отдельной кнопке «Подробнее», которая на короткое время даже появлялась в левом верхнем углу до полной загрузки стилей.

Вместо очередного локального «патча» была проверена вся цепочка Hero: `index.php` → `hero-slider.php` → `hero.css` → `hero.js` → браузерный DOM.

В результате логика стала проще и понятнее:

```text
CMS хранит ссылку слайда
        ↓
hero-slider.php создаёт слайд
        ↓
вся площадь активного слайда становится ссылкой
        ↓
стрелки и точки остаются поверх неё
        ↓
пользователь кликает по текущему Hero
        ↓
открывается ссылка именно этого слайда
```

Отдельная кнопка «Подробнее» больше не нужна.

# Главная задача дня

Закрыть Hero-слайдер как готовый компонент главной страницы: убрать остаточные визуальные артефакты, стабилизировать навигацию и сделать переход к материалу естественным — кликом по самому активному слайду.

---

# 1. Проверка реальной структуры главной страницы

Сначала был проверен актуальный `index.php`.

Подтверждено, что Hero подключается корректно одним компонентом:

```php
<?php require __DIR__ . '/includes/hero-slider.php'; ?>
```

Старого внешнего контейнера `<section class="hero">` вокруг подключения больше нет.

Также был проверен общий `footer.php`: он не содержит повторного подключения `hero.js` и не создаёт двойных обработчиков стрелок.

Это позволило исключить две ложные причины и перейти к фактической логике Hero.

---

# 2. Очистка подключений CSS и JavaScript

В `index.php` оставалась ссылка на промежуточный файл:

```text
hero-day25-additions.css
```

Фактически такого файла в рабочей структуре уже не было.

Настройки Hero были сведены к существующему основному файлу:

```text
/new-home/css/hero.css
```

Для обновлённых CSS и JavaScript добавлена версия в URL, чтобы браузер не продолжал использовать старую копию из кеша.

Принцип:

```text
hero.css?v=новая-версия
hero.js?v=новая-версия
```

Это особенно важно при отладке интерфейса на рабочем сервере: изменение файла на хостинге ещё не означает, что браузер немедленно загрузил именно его.

---

# 3. Стабилизация переключения слайдов

Была отдельно проверена логика `hero.js`.

Исходный алгоритм математически переключал слайд только на один шаг, но использовал постоянный `setInterval`. Для более предсказуемого поведения автопрокрутка переведена на управляемый `setTimeout`.

После ручного действия алгоритм теперь работает по схеме:

```text
остановить текущий таймер
        ↓
переключить ровно один слайд
        ↓
создать новый таймер автопрокрутки
```

Также добавлена защита от повторной инициализации Hero.

Это уменьшает риск ситуации, когда один и тот же блок случайно получает несколько наборов обработчиков событий.

---

# 4. Отказ от отдельной кнопки «Подробнее»

Во время тестирования выяснилось, что отдельная CTA-кнопка уже не даёт преимуществ для текущего дизайна Hero.

Более естественный вариант:

- пользователь наводит курсор на изображение;
- курсор показывает, что слайд активен;
- клик по самому Hero открывает связанный материал.

Поэтому старые элементы были удалены из публичного вывода:

```text
.hero-button
.hero-image-action
.hero-button--image
```

Теперь визуальный Hero не содержит отдельной кнопки перехода.

---

# 5. Весь активный слайд стал ссылкой

В `hero-slider.php` для каждого слайда с корректным `button_url` создаётся прозрачная ссылка:

```html
<a class="hero-slide-link" href="..."></a>
```

Она занимает всю площадь слайда.

При этом URL по-прежнему берётся из той же записи CMS, поэтому никакого второго источника ссылок не появилось.

Логика проста:

```text
слайд 1 → URL 1
слайд 2 → URL 2
слайд 3 → URL 3
```

Какой слайд активен в данный момент — по ссылке того слайда и выполняется переход.

---

# 6. Правильные слои интерфейса

Чтобы полноэкранная ссылка не мешала навигации, элементы разнесены по `z-index`.

```text
z-index 5 → стрелки и точки
z-index 3 → прозрачная ссылка всего слайда
z-index 2 → текст Hero
z-index 1 → затемнение
            изображение
```

Это позволяет одновременно получить два ожидаемых поведения:

- клик по основной площади Hero открывает материал;
- клик по стрелке или точке только переключает слайд и не открывает ссылку.

---

# 7. Диагностика через DevTools вместо догадок

Самая важная часть дня — переход от предположений к проверке того, что браузер реально получил от сервера.

В Console были проверены:

```js
document.querySelectorAll('.hero-slide-link').length
```

и

```js
document.querySelectorAll('.hero-button, .hero-image-action').length
```

Результат показал:

```text
.hero-slide-link = 0
старые кнопки = 4
```

Это означало, что браузер продолжает получать старую HTML-разметку, несмотря на внесённые изменения.

Для дополнительной проверки в новый PHP-компонент был добавлен технический маркер:

```html
data-hero-build="20260829-clickable-v1"
```

Проверка:

```js
document.querySelector('.hero')?.dataset.heroBuild || 'НЕТ МАРКЕРА'
```

сначала вернула:

```text
НЕТ МАРКЕРА
```

То есть проблема была не в CSS: на сервере фактически оставалась старая версия `hero-slider.php`.

Вместо дальнейшего редактирования отдельных фрагментов был подготовлен полный новый файл:

```text

```

В новой версии одновременно зафиксированы:

- получение активных слайдов из `hero_slides`;
- поддержка RU/HU;
- безопасная обработка URL;
- режим с затемнением и режим изображения без затемнения;
- корректный порядок слайдов;
- полноэкранная `.hero-slide-link`;
- отсутствие старых кнопок «Подробнее»;
- стрелки и точки;
- диагностический build-маркер.

После фактической замены рабочего файла новая логика появилась в браузере и Hero заработал ожидаемо.

# 9. Почему исчез «Подробнее» в левом верхнем углу

Краткое появление «Подробнее» до загрузки слайдера было следствием старой HTML-разметки.

Браузер успевал получить обычную текстовую ссылку до применения всех CSS-правил.

После перехода на прозрачную полноэкранную ссылку текста «Подробнее» в публичном HTML больше нет.

Поэтому исчез и сам визуальный артефакт загрузки.
