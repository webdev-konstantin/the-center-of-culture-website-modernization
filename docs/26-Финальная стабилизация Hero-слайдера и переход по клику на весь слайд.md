# Что было сделано — простыми словами

В День 25 у Hero-слайдера появился собственный редактор в CMS.

Задача Дня 26 — довести этот модуль до законченного рабочего состояния на главной странице: чтобы администратор мог управлять слайдами из CMS, а посетитель видел актуальный Hero, последовательно перелистывал его и открывал материал простым кликом по активному слайду.

Итоговая схема стала такой:

```text
редактор Hero в CMS
        ↓
таблица hero_slides
        ↓
публичный hero-slider.php
        ↓
Hero на главной странице
        ↓
стрелки / точки / автопрокрутка
        ↓
клик по активному слайду
        ↓
URL именно этого слайда
```

Главный результат: Hero теперь работает как единый CMS-компонент, а не как набор отдельных PHP-, CSS- и JavaScript-фрагментов.

# Главная задача дня

Получить полностью завершённый Hero-модуль со следующими свойствами:

- содержимое берётся из CMS;
- показываются только опубликованные слайды;
- сохраняется заданный порядок;
- работают два режима изображения;
- каждый слайд хранит собственную ссылку;
- стрелки и точки переключают слайды последовательно;
- автопрокрутка сохраняется;
- весь активный слайд является кликабельной областью;
- отдельная кнопка «Подробнее» не требуется;
- CSS и JavaScript обновляются без проблем со старым браузерным кешем.

---

# 1. Используем CMS как единственный источник содержимого

Редактор Hero, созданный в День 25, остаётся точкой управления слайдами.

Администратор задаёт:

- изображение;
- заголовок;
- короткий текст;
- URL перехода;
- режим отображения;
- порядок;
- статус публикации.

Публичная часть не хранит отдельную копию этих данных.

Принцип:

```text
одна запись в CMS
        ↓
один слайд на главной
```

Это исключает ситуацию, когда содержимое в административной части и на публичной странице расходится.

---

# 2. Подключаем Hero к главной одним PHP-компонентом

Главная страница использует отдельный компонент:

```php
<?php require __DIR__ . '/includes/hero-slider.php'; ?>
```

Сам `hero-slider.php` формирует полноценную секцию Hero.

Поэтому в `index.php` не нужен второй внешний `<section class="hero">`.

Итоговая структура проще:

```text
index.php
   ↓
hero-slider.php
   ↓
готовая разметка Hero
```

---

# 3. Загружаем только нужные слайды

`hero-slider.php` получает данные из таблицы `hero_slides`.

Компонент:

- учитывает текущую локаль;
- выводит только опубликованные записи;
- соблюдает `sort_order`;
- безопасно выводит текстовые значения;
- проверяет URL;
- формирует HTML каждого слайда.

Таким образом, порядок и состав Hero управляются через CMS, а не вручную в `index.php`.

---

# 4. Сохраняем два режима Hero

Для каждого слайда поддерживаются два варианта отображения.

## Режим с затемнением

Используется, когда поверх изображения нужны:

- заголовок;
- короткий текст;
- контрастный затемняющий слой.

## Режим без затемнения

Используется для:

- афиш;
- плакатов;
- готовых рекламных изображений;
- графики, которую важно показать без дополнительного фильтра.

Режим выбирается отдельно для каждого слайда в CMS.

---

# 5. Делаем весь активный слайд ссылкой

Вместо отдельной кнопки «Подробнее» используется одна прозрачная ссылка на всю площадь слайда:

```html
<a class="hero-slide-link" href="..."></a>
```

URL берётся из записи текущего слайда.

Логика получается максимально простой:

```text
слайд 1 → URL 1
слайд 2 → URL 2
слайд 3 → URL 3
```

Пользователь наводит курсор на Hero, видит указатель `pointer` и может открыть материал кликом по любой свободной области активного слайда.

Отдельный текстовый CTA-элемент больше не нужен.

---

# 6. Разделяем кликабельный слайд и навигацию

Полноэкранная ссылка не должна перекрывать стрелки и точки.

Для этого используется понятная иерархия слоёв:

```text
z-index 5 → стрелки и точки
z-index 3 → ссылка всего слайда
z-index 2 → текст Hero
z-index 1 → затемнение
            изображение
```

В результате:

- клик по Hero открывает материал;
- клик по стрелке только перелистывает;
- клик по точке только выбирает нужный слайд.

---

# 7. Стабилизируем JavaScript-навигацию

`hero.js` отвечает только за поведение слайдера:

- определяет текущий активный слайд;
- переключает предыдущий и следующий;
- синхронизирует точки;
- сохраняет автопрокрутку;
- корректно реагирует на ручное переключение;
- не должен инициализировать один и тот же Hero несколько раз.

Главный принцип:

```text
одно действие пользователя
        ↓
одно переключение слайда
```

То есть правая стрелка переводит 1 → 2 → 3, а левая — в обратном порядке.

---

# 8. Оставляем стили Hero в одном рабочем CSS

Публичные стили Hero сосредоточены в:

```text
/new-home/css/hero.css
```

В этом файле находятся:

- размеры Hero;
- позиционирование слайдов;
- активное и неактивное состояние;
- затемнение;
- текстовый слой;
- стрелки;
- точки;
- `.hero-slide-link`;
- адаптивные правила.

Дополнительный промежуточный CSS для Hero не требуется.

---

# 9. Обновляем CSS и JavaScript без старого кеша

При изменении публичных файлов браузер может продолжать использовать предыдущую копию.

Поэтому в `index.php` применяется версия ресурса:

```html
<link rel="stylesheet" href="/new-home/css/hero.css?v=20260829-2">
<script src="/new-home/js/hero.js?v=20260829-1"></script>
```

Это заставляет браузер загрузить актуальный CSS и JavaScript после обновления файлов на сервере.

---

# 10. Добавляем технический build-маркер

Для быстрой проверки версии публичного PHP-компонента в Hero предусмотрен служебный маркер:

```html
data-hero-build="20260829-clickable-v1"
```

Его можно проверить в DevTools:

```js
document.querySelector('.hero')?.dataset.heroBuild
```

Так сразу видно, что браузер получил именно текущую версию `hero-slider.php`.

Это не пользовательская функция, а простой инструмент контроля при дальнейшем обслуживании сайта.

---

# 11. Итоговая структура файлов

Основная рабочая связка Hero выглядит так:

```text
/new-home/admin/hero-slides.php
/new-home/includes/hero-slider.php
/new-home/css/hero.css
/new-home/js/hero.js
/new-home/index.php
```

Роли файлов разделены:

```text
hero-slides.php  → управление содержимым
hero-slider.php  → получение данных и HTML
hero.css         → внешний вид
hero.js          → переключение слайдов
index.php        → подключение готового компонента
```
