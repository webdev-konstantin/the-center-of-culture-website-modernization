
# Выполненные задачи

## 1. Реализация красивых URL через Apache mod_rewrite

В `.htaccess` тестового проекта добавлено правило маршрутизации:

```apache
RewriteRule ^(ru|hu)/news/([a-z0-9-]+)/?$ news.php?locale=$1&slug=$2 [L,QSA,NC]
```

Рабочий формат адреса:

```text
/new-home/ru/news/den-russkogo-yazyka-v-rkc
```

Архитектура перехода:

```text
Красивый URL
        ↓
Apache mod_rewrite
        ↓
news.php?locale=ru&slug=...
        ↓
MySQL
        ↓
Динамическая страница публикации
```

Поддержка старого адреса сохранена, поэтому внедрение выполнено без жёсткого перенаправления и без риска сломать существующие ссылки.

## 2. Поддержка языка в динамической странице

В `news.php` добавлено получение и проверка параметра локали:

```php
$locale = strtolower(
    trim((string) ($_GET['locale'] ?? 'ru'))
);
```

Разрешённые значения:

```php
$allowedLocales = [
    'ru',
    'hu'
];
```

SQL-запрос теперь получает публикацию одновременно по двум значениям:

```sql
WHERE slug = ?
  AND content_type = 'news'
  AND locale = ?
  AND is_published = 1
  AND deleted_at IS NULL
```

Это подготовило шаблон к дальнейшему подключению венгерской версии сайта.

## 3. Заполнение отсутствующих slug

Диагностический запрос показал, что несколько реальных публикаций имели значение:

```text

```

Из-за этого компонент «Другие новости» пропускал их и выводил только одну карточку.

Для публикаций были добавлены уникальные значения:

```text

muzykalnyy-podarok-dlya-gostey-rkc
den-russkogo-yazyka-v-rkc
```

После обновления базы все реальные новости начали корректно участвовать в динамической выборке.

## 4. Завершение компонента «Другие новости»

Обновлён файл:

```text
/docs/new-home/includes/latest-news.php
```

Компонент теперь:

- использует текущую локаль;
- исключает открытую публикацию;
- получает только опубликованные и неудалённые записи;
- игнорирует записи без `slug`;
- сортирует публикации по убыванию даты;
- выводит не более трёх карточек;
- формирует красивые URL.

Ключевой лимит:

```php
$otherNewsLimit = 3;
```

Основной запрос:

```sql
SELECT
    id,
    title,
    slug,
    image_path,
    publication_date
FROM home_feed_items
WHERE content_type = 'news'
  AND locale = ?
  AND is_published = 1
  AND deleted_at IS NULL
  AND slug IS NOT NULL
  AND slug <> ''
  AND slug <> ?
ORDER BY
    publication_date DESC,
    id DESC
LIMIT 3
```

## 5. Безопасное удаление тестовой публикации

Тестовая новость не была удалена физически из таблицы.

Вместо `DELETE` применено мягкое удаление:

```sql
UPDATE home_feed_items
SET
    is_published = 0,
    deleted_at = NOW()
WHERE id = 6
  AND slug = 'testovaya-novost'
LIMIT 1;
```

Результат:

- публикация исчезла с главной страницы;
- публикация исчезла из вертикального блока;
- красивый URL перестал открывать материал;
- запись осталась в базе для возможного восстановления;
- архитектура будущей корзины CMS сохранена.

## 6. Перестройка макета страницы новости

Структура `news.php` была приведена к логичной двухколоночной схеме.

Итоговая архитектура:

```text
news-page
    ↓
news-layout
    ├── news-article
    │      ├── дата
    │      ├── заголовок
    │      ├── теги
    │      ├── изображение
    │      └── полный текст
    │
    └── news-sidebar
           ├── ссылка «Вернуться на главную»
           └── блок «Другие новости»
```

Дата, заголовок и изображение теперь относятся непосредственно к левой колонке статьи.

Ссылка:

```text
← Вернуться на главную
```

перенесена в правую колонку над блоком других публикаций.

## 7. Переход к области чтения

В основной контейнер страницы добавлен якорь:

```html
<main
    class="news-page"
    id="news-reading"
>
```

Ссылки боковой колонки теперь формируются с фрагментом:

```text
#news-reading
```

Пример:

```text
/new-home/ru/news/den-russkogo-yazyka-v-rkc#news-reading
```

При переходе между публикациями браузер открывает новую страницу сразу в области чтения, а не возвращает пользователя к верхней части большого хедера.

## 10. Устранение двойного экранирования изображения

Переменная пути изображения теперь хранит исходное значение:

```php
$imagePath = trim(
    (string) ($news['image_path'] ?? '')
);
```

Экранирование выполняется только в момент вывода:

```php
src="<?= htmlspecialchars(
    $imagePath,
    ENT_QUOTES,
    'UTF-8'
) ?>"
```

Это соответствует корректному принципу обработки данных:

```text
MySQL
    ↓
исходное значение PHP
    ↓
экранирование при выводе HTML
```

## 11. Подготовка карусели главной страницы к красивым URL

Проверен файл:

```text
/docs/new-home/api/news-carousel.php
```

Карусель уже получает до восьми материалов:

```sql
LIMIT 8
```

Поэтому JavaScript менять не потребовалось: `content-carousel.js` автоматически рассчитывает количество страниц по числу карточек.

В `news-carousel.php` добавлено формирование адреса по `slug`:

```php
$slugValue = trim(
    (string) ($item['slug'] ?? '')
);

if ($slugValue !== '') {
    $targetUrl =
        '/new-home/ru/news/' .
        rawurlencode($slugValue);
}
```

Поле `target_url` сохранено как запасной вариант для старых записей без `slug`.

При выводе добавлено безопасное экранирование:

```php
href="<?= htmlspecialchars(
    $targetUrl,
    ENT_QUOTES,
    'UTF-8'
) ?>"
```

и:

```php
src="<?= htmlspecialchars(
    $imagePath,
    ENT_QUOTES,
    'UTF-8'
) ?>"
```
